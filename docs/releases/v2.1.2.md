## mote v2.1.2

Fix release: input, closing and drawing bugs on the Linux ports, plus editor
fixes found while splitting up the core.

### Fixes

- **Wayland, SDL, fbdev** — closing the window with unsaved changes no longer hangs; the unsaved-changes question shows up as it should
- **X11** — Cyrillic and other non-Latin text is drawn with the built-in font, so it no longer depends on the X server's fonts (Xwayland has only Latin-1); zoom works and the window title is UTF-8
- **SDL2, X11, Wayland** — shortcuts work on a Russian or other non-Latin layout, whichever layout comes first; Wayland keys repeat while held
- **fbdev** — fills the screen, hides the console text and cursor, reads every keyboard (a gaming mouse no longer takes over), ignores keys while another console is shown and refuses to start inside a desktop session unless `MOTE_FB` is set
- **Terminal** — Ctrl/Alt/Shift with arrows and F-keys decode correctly in more terminals; Shift+F3 and Ctrl+] work
- **Windows** — AltGr no longer fires Ctrl shortcuts, Alt+F4 closes, the window size is saved correctly, and paths and titles are UTF-8
- **DOS** — `-g` accepts 40..80 x 10..25; saving no longer loses data
- **Find** — the case option was inverted for regex, and `^` / `$` now match at every line
- **Editor** — Esc in Save As after an unsaved-changes question no longer leaves a pending quit; F9 jumps to the nearest bookmark; word wrap is updated after edits and tab switches; duplicate line is one undo step
- **Toggle comment** uses each language's own style (`<!-- -->` for HTML / XML / Markdown, `/* */` for CSS, `--` for SQL, `#` for Makefiles)
- **Quick open** — j and k go to the filter
- CP1251 files with a real U+FFFD character load correctly

The Web build now starts with an empty document.
